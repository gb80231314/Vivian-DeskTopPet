# 语音交互功能方案（Hi, Vivian 唤醒）

为 Vivian 桌面宠物增加语音交互能力：用户说出唤醒词 **"Hi, Vivian"** 后，宠物进入聆听状态，识别语音指令并做出回应。

> **Designed by Louis_Qi for Vivian**

---

## 1. 功能目标

| 能力 | 说明 |
|---|---|
| 麦克风检测 | 启动时自动检测电脑是否有可用麦克风，无麦克风时优雅降级（禁用语音功能、气泡提示） |
| 唤醒词检测 | 后台持续监听 "Hi, Vivian"，本地运行、低 CPU 占用 |
| 语音指令识别 | 唤醒后录制一句话，转成文字（STT） |
| 智能回应 | 根据意图触发宠物动作 + 语音回应（复用现有 voicepacks 情绪语音） |
| 状态可视化 | 宠物在"待命 / 聆听 / 思考 / 回应"之间切换动画状态 |

---

## 2. 麦克风检测（前置条件，必须先做）

### 2.1 检测方案

使用 `sounddevice`（PortAudio 封装，跨平台、pip 直接安装，Windows 无需额外编译）：

```python
import sounddevice as sd

def detect_microphone():
    """返回 (可用性, 默认输入设备名或原因)"""
    try:
        devices = sd.query_devices()
    except Exception:
        return False, "音频系统初始化失败（PortAudio 不可用）"

    inputs = [d for d in devices if d["max_input_channels"] > 0]
    if not inputs:
        return False, "未检测到任何输入设备"

    default_in = sd.query_devices(kind="input")  # 可能抛异常
    if default_in is None:
        return False, "未设置默认麦克风"
    return True, default_in["name"]
```

### 2.2 检测时机与降级策略

1. **启动时检测**（`qpet_app.py` 初始化阶段）：
   - 检测到麦克风 → 加载语音模块，托盘菜单显示"语音交互 ✓"
   - 未检测到 → 跳过语音模块加载（零开销），托盘菜单显示"语音交互（未检测到麦克风）"灰色项，气泡提示一次："没找到麦克风，语音功能未开启"
2. **运行时重试**：托盘菜单提供"重新检测麦克风"，用户插上 USB 麦克风后无需重启程序。
3. **真实流测试**：设备枚举成功不代表可录音（可能被系统禁用）。首次启用时开一个 0.3 秒的 `InputStream` 试录，捕获 `PortAudioError` 则判定不可用。

### 2.3 Windows 特别注意事项

- **系统隐私权限**：Windows 10/11 的"设置 → 隐私 → 麦克风"中，若"允许桌面应用访问麦克风"被关闭，枚举仍会列出设备但录音失败或得到静音。试录阶段若发现全零数据，提示用户去系统设置开启。
- **设备热插拔**：USB 麦克风拔出后流会中断，需要捕获回调异常并自动回到"未检测"状态。
- **默认设备切换**（如插耳机）：定期（如每 30 秒）或打开流失败时重新 `query_devices`。

## 3. 技术选型

### 3.1 唤醒词检测（"Hi, Vivian"）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **openWakeWord**（推荐） | 完全开源免费、本地 ONNX 推理、CPU 占用极低（单核可跑 15+ 模型）、官方 Colab 笔记本可用 TTS 合成数据训练自定义词、内置 Silero VAD 降误触 | 预训练模型只有英文（"Hi, Vivian" 恰好是英文，可行）；Windows 仅支持 onnxruntime 推理（够用） | ✅ 主选 |
| Picovoice Porcupine | 精度高、免费个人版支持自定义词 | 闭源、需 AccessKey（联网激活）、商用需授权 | 备选 |
| Vosk + 文本匹配 | 中英文都行 | 模型 40MB+、始终跑满语音识别、CPU 占用高 | 不选 |

**自定义模型训练**：openWakeWord 支持用 TTS 合成语音自动生成训练数据，官方 Colab 笔记本 `automatic_model_training.ipynb` 一站式完成，产出 `hi_vivian.onnx`（约 1-2MB），训练约需 1-2 小时（Colab 免费 T4 即可）。"Hi, Vivian" 三个音节、含硬辅音，是理想的唤醒词结构。

### 3.2 语音识别（STT，唤醒后的一句话）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **faster-whisper（small/int8）**（推荐） | 本地运行、中英文混合识别好、GGML int8 模型约 75MB、CPU 实时率 >1 | 模型文件大、首次加载 1-2 秒 | ✅ 主选（本地隐私优先） |
| FunASR（Paraformer） | 中文识别最强 | 中文生态为主、打包链路复杂 | 中文精准度不够时再考虑 |
| 腾讯云/百度 ASR | 零体积、识别最准 | 需联网 + 付费 + 隐私顾虑 | 可选插件式支持 |

### 3.3 语音回应（TTS）

**分两层，优先复用现有资产：**

1. **固定情绪语音（零成本）**：`assets/voicepacks/甜嗓默认/` 已有 angry / failed / greet / happy / neutral / wave / wink 七种情绪 mp3。唤醒回应、常见指令反馈直接映射播放（如唤醒 → `greet.mp3`，听不懂 → `failed.mp3`）。
2. **动态内容 TTS（可选，二期）**：对需要动态合成的回复（如报时、读日程），接入 edge-tts（免费、微软神经网络音色、无需 API Key）。默认关闭，设置中开启。

## 4. 系统架构

### 4.1 状态机

```
IDLE（待命，持续跑唤醒词检测）
  │  "Hi, Vivian" 命中 (score ≥ 0.5)
  ▼
AWAKE（挥手动画 + 播放 greet.mp3，约 0.8s）
  ▼
LISTENING（聆听动画，VAD 检测语音开始）
  │  静默 1.5s 或超时 8s
  ▼
PROCESSING（思考动画，跑 STT + 意图解析）
  │
  ├─ 识别到指令 → 回应动作 + 情绪语音 → IDLE
  └─ 无法识别 → 摇头 + failed.mp3 → IDLE
```

### 4.2 线程模型（关键：复用 V1.0.2 的主线程队列模式）

音频是强实时任务，**绝不能**放在 Tk 主线程或直接操作 UI。沿用已验证的 `_tk_queue` + `_post_to_main()` 投递模式：

```
┌─ Tk 主线程 ──────────────────┐    ┌─ 音频线程（daemon）──────────────┐
│ 动画渲染 / 气泡 / 托盘        │    │ sounddevice InputStream 16kHz     │
│ _drain_tk_queue 每 100ms     │◄───┤  → openWakeWord.predict(帧)       │
│ 收到事件后切状态机            │queue│  → 命中后录指令 → Silero VAD 断句  │
└──────────────────────────────┘    │ STT 线程池：faster-whisper 转写    │
                                    │  → 结果 _post_to_main(意图)      │
                                    └──────────────────────────────────┘
```

- 音频线程只投递**事件**（`("wake", score)`、`("transcript", text)`），不触碰任何 Tk 对象 —— 这是 V1.0.2 退出崩溃修复的同一套纪律。
- `_quit()` 退出时需先停音频流（`stream.stop()`）、设 `self._closing` 让音频线程自然退出，再销毁 Tk —— 避免重蹈跨线程销毁的覆辙。
- STT 模型惰性加载：唤醒命中后才首次加载 whisper，避免影响启动速度。

### 4.3 音频参数约定

| 参数 | 值 | 说明 |
|---|---|---|
| 采样率 | 16000 Hz | openWakeWord / whisper 标准输入 |
| 帧长 | 1280 samples（80ms） | openWakeWord 推荐帧长倍数 |
| 格式 | int16 单声道 | sounddevice 录 float32 需转换 |
| 唤醒阈值 | 0.5 起步 | 误触多调到 0.6-0.7，漏识调到 0.3-0.4 |
| VAD | Silero（openWakeWord 内置 `vad_threshold=0.6`） | 抑制非语音噪声误触发 |
| 冷却时间 | 3 秒 | 防止连续重复触发 |

## 5. 指令与意图设计（一期从规则开始）

一期不接 LLM，用关键词规则 + 宠物现有能力映射，保证零成本、零延迟：

| 用户说 | 意图 | 宠物行为 |
|---|---|---|
| 打招呼 / 你好 / hi | greet | 挥手动画 + greet.mp3 |
| 跳舞 / 舞蹈 / dance | dance | 切换随机动画序列 |
| 抱抱 / 摸摸 | comfort | 眨眼/亲昵动画 + happy.mp3 |
| 现在几点 / 几点了 | time | 气泡报时（动态 TTS 二期） |
| 隐藏 / 出来 / 待着吧 | visibility | 切换显示/隐藏 |
| 拜拜 / 退出 / 再见 | quit | 确认气泡 + 退出 |
| （其他） | fallback | 歪头 + failed.mp3 |

二期再评估接入 mcp_server.py 已有的本地 MCP 通道，把 STT 文本交给 LLM 生成回应。

```json
{
  "voice": {
    "enabled": true,
    "wake_threshold": 0.5,
    "wake_cooldown_sec": 3,
    "listen_timeout_sec": 8,
    "silence_end_sec": 1.5,
    "input_device": null,
    "tts_mode": "voicepack"
  }
}
```

托盘菜单新增：
- 语音交互 开/关（实时切换音频线程启停）
- 重新检测麦克风
- （调试）显示唤醒分数

## 7. 隐私设计（默认本地优先）

- 唤醒词检测、STT **全部本地运行**，音频数据不出机器、不落盘（环形缓冲，仅保留最近 80ms 帧用于推理）。
- 录制的指令音频转写后立即丢弃原始音频。
- 若二期接入云端 ASR/TTS，必须在设置中显式开启并标注"将使用网络"。
- README 中明确说明"麦克风只在本地处理"。

## 8. 打包与体积影响

| 新增依赖 | 体积影响 | 打包注意 |
|---|---|---|
| sounddevice + PortAudio DLL | ~1 MB | PyInstaller 需收集 `sounddevice` 的 DLL（`--collect-all sounddevice`） |
| openwakeword + onnxruntime | ~40 MB（Windows 用 onnxruntime） | `--collect-data openwakeword`；自定义模型 `hi_vivian.onnx` 放 `assets/models/` |
| faster-whisper + 模型 | 模型 75MB（**不打进安装包**） | 首次使用时下载到 `%APPDATA%/QPet/models/`，或安装包可选组件 |
| numpy | 已是依赖树内 | — |

预估：安装包从 26.7MB 增至 **约 70MB**（含 onnxruntime + 唤醒模型，不含 whisper 大模型）。若想控制体积，可把语音功能做成**可选组件**：主包不带，安装时勾选或首次启用时下载。

PyInstaller 隐藏导入需注意：`onnxruntime`、`sounddevice`、`scipy`（whisper 依赖）均需 `--collect-all` 或 hiddenimports 显式声明；打包后必须在无 Python 环境的干净机器上做冒烟测试（麦克风检测 + 唤醒全链路）。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 自训练唤醒词误触率偏高 | 阈值 + VAD 双重过滤；Colab 笔记本支持自定义验证模型做声纹二次过滤 |
| Windows 麦克风权限被禁 | 试录检测静音数据 → 气泡引导用户开启系统权限 |
| 音频线程导致退出崩溃（历史教训） | 严格走 `_post_to_main` 队列；`_quit` 先停流再销毁；纳入退出冒烟测试 |
| whisper 首次加载慢 | 惰性加载 + 加载期间"思考"动画；可选开机预热 |
| 安装包膨胀 | 语音组件可选安装 / 模型运行时下载 |
| 用户被误唤醒打扰 | 默认开启冷却 3s；托盘一键关闭；唤醒后仅动画提示、确认说话才录音 |
